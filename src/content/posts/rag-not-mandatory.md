# RAG 是公司必備嗎？我看未必。

最近在抖音看到一間陸企的高管面試 AI 員工，直接批評面試者不懂 RAG。

看完只覺得：**懂 RAG 是專業，不懂就判死刑，是傲慢。**

AI Agent 還在快速演進，RAG 當然有用，但遠不到「公司必備」的程度。把 RAG 當成唯一解法，就像以為會用螺絲起子，天下就沒有螺絲解決不了的問題。

不使用傳統 RAG，Agent 一樣能做知識檢索。

例如，**Ontology（本體論）搭配向量檢索，再加上開源 EmbeddingGemma 2**，就值得評估。與其盲目堆疊架構，不如先想清楚：怎麼讓 Agent 找得更準、存得更少、維護得更輕鬆。

- [站在巨人肩上：小企業不必砸錢買模型設備，也能兼顧隱私與安全](/wip/sme-open-weights-privacy)

### RAG 不是不好，而是別把它當信仰。

1. **檢索不等於精準。** 文件切分、索引品質與召回率都會影響結果；找不到資料，或只找到半套，一樣會出問題。

2. **語意相似不等於答案正確。** 向量檢索可能找出「看起來很像、實際上不對」的內容。

3. **架構不是零成本。** 文件更新、索引維護、檢索流程與上下文管理，都需要額外成本。

4. **技術迭代不是按個更新鍵就好。** 更換模型不一定要重做整套 RAG，但若涉及 Embedding 模型更換，通常就得評估重新向量化與索引相容性。

當然，Ontology 和向量檢索也不是萬靈丹，照樣有建模、維護與檢索品質的問題。
